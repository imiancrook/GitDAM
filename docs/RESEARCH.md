# What people actually complain about: DAM, creative versioning, and binary VCS

Research synthesis, September 2026. Four sweeps: enterprise/mid-market DAM buyers and users; designers and agencies; video/VFX/post-production; and the "version control for binary assets" competitive landscape. The point is to test [VISION.md](./VISION.md) against evidence, so §7 (scorecard) and §8 (changes to the plan) are the payload; §1–§6 are the evidence.

**How to read the citations.** The research environment could not fetch full pages from G2, Capterra, Trustpilot, Reddit, Adobe Community, Unity Discussions or most vendor sites (egress policy); GitHub and GitLab issue pages were read in full. Everything else is quoted from search-index excerpts of the linked page. Treat quotes as accurate-in-substance and **re-verify wording against the URL before using it externally**. No Reddit thread content was retrievable at all; where "Reddit says" would normally appear, the evidence comes from Adobe Community, Creative COW, Blackmagic and Unity forums, Figma's forum, and GitHub issue trackers instead, which are arguably better sources.

## 1. Cross-cutting findings

Ten things that showed up in more than one community, in rough order of how often and how strongly.

1. **The DAM that sits apart from daily work gets bypassed.** Forrester's Q3 2025 survey (n=313): "DAM that sits apart from daily workflows gets bypassed"; teams still on email and shared drives report the lowest adoption. AVP's description of the typical outcome: "a well-organized library that nobody outside the marketing team uses—technically successful, operationally inert." Orange Logic: "the DAM was built for one type of user and tolerated by the rest." [Papirfly/Forrester](https://www.papirfly.com/blog/digital-asset-management/forrester-dam-content-operations/), [AVP](https://www.weareavp.com/dam-buy-in-guide/), [Orange Logic](https://www.orangelogic.com/dam-blog/understanding-the-role-of-scale-in-dam-user-adoption)

2. **Naming is the version control system, and it fails constantly.** "final_v7_REAL_final.mp4", "FINAL_v4_USE_THIS_ONE.psd", and clients "commenting on the wrong cut" appear in every community. Air (a DAM vendor) admits "file naming conventions have become makeshift version control systems that were never built to carry that weight." Editors pay for a script (Version Raptor) whose only job is to bump the number in the filename. [Air](https://air.inc/resources/version-control-for-creative-files), [PetaPixel](https://petapixel.com/2015/07/22/this-is-how-everyone-names-their-final-psd-files/), [playpause](https://playpause.io/client-approval-workflow), [Version Raptor](https://hyperbrew.gumroad.com/l/version-raptor)

3. **Last save wins, and there is no way back.** Creative COW on shared Premiere projects: "whomever saves last is the version that is saved." Frame.io's own guide: "whoever clicks 'save' last will overwrite all the work done by another editor." Adobe's answer to "How to recover a file accidentally saved over in Photoshop" is, in substance, no. Corrupted project files with "autosave dutifully saving corrupted files" are a recurring thread. [Creative COW](https://creativecow.net/forums/thread/locking-premiere-pro-projects/), [Frame.io guide](https://workflow.frame.io/guide/collaborative-editing-premiere-pro), [Adobe Community](https://community.adobe.com/questions-712/how-to-recover-a-file-accidentally-saved-over-in-photoshop-1085561), [Adobe bug report](https://community.adobe.com/bug-reports-728/premiere-pro-2025-project-file-corrupted-autosaves-also-won-t-open-1331881)

4. **Sync tools create conflicts instead of resolving them.** Dropbox's definition of a conflicted copy is a renamed duplicate with no merge. An Illustrator user gets one "every time" they switch machines and does "work twice"; a teammate ended up with "thousands of conflicted copy files." Creative Cloud Libraries reported "Up To Date" with most files missing. Adobe cloud documents delete unmarked versions after 30 days. [Dropbox](https://help.dropbox.com/organize/conflicted-copy), [Adobe Community](https://community.adobe.com/questions-606/why-am-i-still-getting-conflicted-copies-why-doesn-t-it-update-sync-to-the-most-recent-change-ver-574627), [Adobe Community](https://community.adobe.com/bug-reports-157/library-sync-complete-but-files-missing-from-library-on-web-or-for-other-users-sync-failing-in-the-1487036), [Adobe Help](https://helpx.adobe.com/creative-cloud/apps/work-with-cloud-documents/manage-and-restore-files/revert-to-earlier-version.html)

5. **Locks are the collaboration primitive for binaries, and every existing implementation is clunky.** Every artist-facing VCS (Perforce, Unity VCS/Gluon, Diversion, Anchorpoint, SVN) leads with exclusive locks. Git LFS locking has open bugs: wrong lock state outside repo root, files stuck read-only after force-unlock, ~8 s per file in TortoiseGit so 100 files means 26 minutes. Anchorpoint reimplements locking outside LFS entirely. Premiere's own project locking is a preference that "has been reported broken." [git-lfs #5891](https://github.com/git-lfs/git-lfs/issues/5891), [git-lfs #3733](https://github.com/git-lfs/git-lfs/issues/3733), [TortoiseGit #3738](https://gitlab.com/tortoisegit/tortoisegit/-/issues/3738), [Anchorpoint](https://www.anchorpoint.app/features/git-for-artists), [Adobe Community](https://community.adobe.com/t5/premiere-pro-discussions/premiere-pro-cc-2019-not-locking-projects/m-p/10386015)

6. **Feedback is scattered and not attached to the version it was about.** "Feedback scattered across email, Slack, marked-up PDFs, phone calls" makes "somebody on the team a full-time feedback wrangler." Ziflow: 67% of unplanned revision rounds come from vague, unstructured or late client feedback. Frame.io V4's most-hated bug: comment markers "constantly revert to refer to the older version of the sequence." Without a tool, editors "translate prose back into timestamps and guess which export the client actually watched." [Feedbucket](https://feedbucket.app/blog/design-feedback-tools), [Ziflow](https://www.ziflow.com/blog/client-proofing-for-agencies), [Adobe bug report](https://community.adobe.com/bug-reports-728/frame-io-v4-keeps-overwriting-comments-markers-in-premiere-pro-pro-1332248), [playpause](https://playpause.io/client-approval-workflow)

7. **"Which one did the client approve?" is a legal problem, not a UX one.** "Implied approval is the source of more post-project disputes than almost anything else in agency work." A post-production writeup claims 82% of agency overruns involving client disputes cite the absence of a formal approval record. [Aligno](https://aligno.io/blog/design-approval-process), [playpause](https://playpause.io/blogs/video-review-and-approval-for-post-production-studios)

8. **Pricing is punished for per-seat, guest fees, opacity and surprise bills.** Canto charges for guest viewers; Bynder charges for admins and "every single time you update your software"; Frontify's MAU pricing is unforecastable; Cloudinary credits "burn at different rates"; Air's Trustpilot has "impossible to cancel" and a jump "from 6EUR to 250EUR"; 93% of media organizations report unexpected cloud storage fees; GitHub's metered LFS bills the owner for every clone including CI; LucidLink costs "increase quickly and silently." Unity just moved Unity VCS to **free seats plus $0.14/GB**, and Artstash sells flat pricing with unlimited users. The market is telling vendors what it wants. [fast.io on Canto](https://fast.io/resources/best-dam-software/), [Bynder/Capterra](https://www.capterra.com/p/122257/Bynder/), [Frontify/G2](https://www.g2.com/products/frontify/reviews?qs=pros-and-cons), [Cloudinary/G2](https://www.g2.com/products/cloudinary/reviews?qs=pros-and-cons), [Air/Trustpilot](https://www.trustpilot.com/review/air.inc), [MASV](https://massive.io/file-transfer/cloud-archive-benefits-challenges-and-best-practices), [GitHub LFS discussion](https://github.com/orgs/community/discussions/61362), [Unity pricing](https://support.unity.com/hc/en-us/articles/34748492914964-Understanding-Unity-DevOps-charges), [Artstash](https://artstash.io/pricing)

9. **Big files break browsers and budgets.** An editor spent four days trying to download an 86 GB file that "kept getting canceled around the 50 or 60 gigabyte mark"; Frame.io users download "76 files individually"; Bynder "will freeze while uploading large volumes"; Git "stores full copies of all files that have ever existed, and once a large file is added it basically cannot be removed"; a 1 GB LFS repo cloned by 100 people burns a year's bandwidth allowance. [ashrafali.net](https://ashrafali.net/the-perils-of-large-file-transfers-over-web-browsers-aka-why-wetransfer-is-tough-to-use/), [Frame.io/Capterra](https://www.capterra.com/p/148214/Frame-io/reviews/), [Bynder/Capterra](https://www.capterra.com/p/122257/Bynder/), [HN](https://news.ycombinator.com/item?id=44916783), [GitHub discussion](https://github.com/orgs/community/discussions/62051)

10. **Metadata is a burden nobody does, and search then fails.** Real Story Group: "metadata policies and standards are often avoided or postponed in many organizations"; Bynder tagging is "a very manual process"; Brandfolder users "accidentally bulk tag the wrong assets"; Filecamp's search is "almost useless"; Canto's search "slows past roughly 100,000 assets"; misspellings in metadata make assets unfindable in Acquia. 83% of employees have recreated an asset they couldn't find. [Real Story Group](https://realstorygroup.com/Blog/metadata-management-dams-still-inadequate), [Bynder/G2](https://www.g2.com/products/bynder/reviews?qs=pros-and-cons), [Brandfolder/Capterra](https://www.capterra.com/p/133103/Brandfolder/reviews/?page=4), [Filecamp/Capterra](https://www.capterra.com/p/133218/Filecamp/reviews/), [Canto review](https://photolibsoftware.com/reviews/canto/), [iBase stats](https://www.ibase.com/news/insight-six-digital-asset-management-statistics-you-cant-ignore.html)

## 2. Enterprise and mid-market DAM (Bynder, Brandfolder, Canto, AEM, Acquia, Aprimo, MediaValet, Frontify, Air, Dash, Filecamp, Cloudinary)

What DAM buyers are sold: a brand portal with tagging, search and sharing. What they complain about:

- **Adoption and governance.** ResourceSpace: poor adoption "is one of the key reasons that many DAM implementations fail"; a DAM without governance "becomes disorganized at roughly the same rate as the shared drive it replaced" (AVP). 37% of orgs switching DAMs name low adoption as the top challenge; 41% name silos. [ResourceSpace](https://www.resourcespace.com/blog/6-reasons-dam-implementations-fail), [AVP forecast](https://www.weareavp.com/dam-executive-forecast-2025/)
- **Versioning is shallow.** No review said "no rollback" in those words, but: Frontify "can't have a versioning of each page"; Bynder's "Additional Assets" can't be reordered or viewed without downloading; Brandfolder's "ways to use the platform for works in progress are not very intuitive"; Daminion notes most DAMs implement versions "by creating new physical copies or by tracking changes to metadata." DAMs are built for *finished* assets; work in progress is out of scope for them. [Frontify/Capterra](https://www.capterra.com/p/183904/Frontify/reviews/?page=2), [Bynder/G2](https://www.g2.com/products/bynder/reviews?qs=pros-and-cons), [Brandfolder/G2](https://www.g2.com/products/brandfolder/reviews), [Daminion](https://daminion.net/articles/tips/dam-version-control/)
- **Tool integration is missing.** Bynder users still "looking forward to implementing the Adobe InDesign/Photoshop/Illustrator integration"; Acquia lacks INDD support; Air's desktop app "would often not sync"; Adobe's own forum has a standing "DAM that integrates with Adobe products" thread. [Brandfolder roundup of G2](https://brandfolder.com/resources/digital-asset-management-software-reviews/), [Acquia/Capterra](https://www.capterra.com/p/76774/Widen-Collective/reviews/?page=9), [Air/G2](https://www.g2.com/products/air-labs-inc-air/reviews), [Adobe Community](https://community.adobe.com/questions-617/dam-that-integrates-with-adobe-products-indesign-photoshop-etc-446851)
- **Performance with large libraries and video.** Bynder: "slower video upload time", freezes on bulk upload, a developer measuring 15 s per API call; MediaValet: "playback stalls or failures"; Brandfolder: "slowdowns when working with large numbers of assets"; Air: "beach balling and hangs requiring force quit." [Bynder SDK issue](https://github.com/Bynder/bynder-js-sdk/issues/43), [MediaValet/Capterra](https://www.capterra.com/p/124632/MediaValet/reviews/), [Air/Capterra](https://www.capterra.com/p/203256/Air/reviews/)
- **No duplicate detection** is a named gap for Bynder and Canto; 51% of marketers lose money on assets rebuilt because nobody could find the original. [Frontify on Bynder](https://www.frontify.com/en/guide/bynder-alternatives), [Brandfolder/Demand Metric](https://brandfolder.com/resources/digital-asset-management-report-2023/)
- **External sharing and permissions.** MediaValet: "confusing external-sharing options", "not an easy way for external individuals to submit materials"; AEM: "surprisingly facile access controls only allow you to set permissions on folder"; Filecamp can't bulk-edit permissions. [MediaValet/G2](https://www.g2.com/products/mediavalet/reviews?qs=pros-and-cons), [Real Story Group on AEM](https://www.realstorygroup.com/Blog/real-story-adobe-dam)
- **Implementation cost and stagnation.** AEM "required special hardware and servers"; Aprimo "$20,000 to over $100,000 annually before implementation"; enterprise vendors want "$50k plus 6 months to implement"; a six-month adoption curve with 40% higher failure when rushed. Post-acquisition: Brandfolder "hasn't meaningfully changed" in four years, Acquia "2+ years to get feature parity", MediaValet's redesign "a step backwards." [Aprimo review](https://photolibsoftware.com/aprimo-review/), [Filecamp on pricing](https://filecamp.com/blog/digital-asset-management-pricing/), [Activo](https://www.activo-consulting.com/dam-knowledge/the-hidden-crisis-behind-digital-asset-management-failures), [Brandfolder/G2](https://www.g2.com/products/brandfolder/competitors/alternatives)
- **Lock-in.** DAM News on the EU Data Act: platforms "remain architected in ways that make portability difficult"; folderless DAMs lose structure on export; Acquia metadata "does not write back into the asset when downloaded"; Air gates bulk export behind Enterprise. [DAM News](https://digitalassetmanagementnews.org/features/the-eu-data-act-vendor-lock-in-and-the-walled-garden-problem-in-dam/), [Mediagraph](https://www.mediagraph.io/solutions/compared-to-bynder)

## 3. Designers and agencies

- **Overwrite and no history.** Illustrator has no history panel at all (long-running request). "PS 2020 saved file reverted to older version on its own, lost a whole day's work." InDesign teams frame the problem as "who gets to overwrite whom and how to track that." [Adobe Community (Illustrator)](https://community.adobe.com/t5/illustrator-discussions/give-us-a-history-panel-in-illustrator/m-p/13113756), [Adobe Community (PS)](https://community.adobe.com/t5/photoshop-ecosystem-discussions/ps-2020-saved-file-reverted-to-older-version-on-its-own-lost-a-whole-day-s-work/m-p/13702388), [Adobe Community (InDesign)](https://community.adobe.com/questions-671/no-access-to-review-issue-when-multiple-designers-are-updating-same-file-886892)
- **Figma is the reference point, and its limits are instructive.** What people praise: "every design decision is both traceable and reversible"; branching as "alternate realities for your designs." What they hate: branching is Organization/Enterprise only ("$33/editor each month just for this feature"); history without labels is unsearchable; the conflict UI gives "no indication of what or where conflicts are... a nightmare"; concurrent edits to different parts of the same frame are flagged as conflicts; merges hit "file out of memory"; Devexperts published "Why Branching in Figma Didn't Work for Us." The forum thread "Git Like versioning" runs multiple pages. [designproject](https://designproject.io/blog/figma-version-control/), [Figma forum: branching plan](https://forum.figma.com/suggest-a-feature-11/branching-feature-for-professional-plan-31418), [Figma forum: conflicts](https://forum.figma.com/suggest-a-feature-11/need-a-better-solution-for-resolving-branch-conflicts-42217), [Figma forum: false conflicts](https://forum.figma.com/t/concurrent-main-and-branch-changes-are-considered-conflicts-when-they-shouldnt-be/18787), [Devexperts](https://medium.com/devexperts/why-branching-in-figma-didnt-work-for-us-and-how-we-manage-design-versions-now-96c05a3d0590), [Figma forum: git-like](https://forum.figma.com/t/git-like-versioning/355)
- **Git itself is the wrong shape.** "Even the tiniest change in a large Sketch file means storing the whole, large file in its entirety again"; IBM Plex removed design sources from its repo because it was "plainly too large"; one user's repo *grew* from 10 GB to 13.3 GB after adopting LFS; binary conflicts are "all-or-nothing"; a real team (Firefund) makes designers install git and git-lfs and run `git lfs pull` before touching anything. [Medium](https://medium.com/@kellyleigh/using-git-for-design-file-storage-53c59a195094), [IBM Plex #554](https://github.com/IBM/plex/issues/554), [git-lfs #5950](https://github.com/git-lfs/git-lfs/issues/5950), [Firefund](https://github.com/Firefund/firefund-lfs)
- **Why the last wave died (Abstract, Kactus, Plant, Pixelapse, LayerVault).** Abstract sunsets January 31, 2026. All were Sketch-only; when Sketch shipped its own cloud and Figma made multiplayer and history native, the category evaporated. Pixelapse was bought by Dropbox in 2015 and absorbed within a year; LayerVault closed the same month. Lesson: a versioning layer bound to one tool dies when that tool adds versioning. [Sketch forum](https://forum.sketch.com/t/abstract-will-officially-sunset/5901), [Kactus](https://github.com/kactus-io/kactus), [TechCrunch](https://techcrunch.com/2015/01/26/dropbox-acquires-pixelapse/), [VentureBeat](https://venturebeat.com/business/dropboxs-acquisition-of-pixelapse-is-not-enough-to-save-competitor-layervault-from-closing)
- **Review tools.** Frame.io: "difficult to know what you're sharing", "clients can be put off by it because it can look a little overwhelming"; Ziflow: "comment management across versions confuses reviewers", "training clients can take some time"; Markup.io removed its free and small-business tiers with no grandfathering (a "350% increase"). The praise, by contrast, goes to tools where "clients rarely need a tutorial." [Frame.io/G2](https://www.g2.com/products/frame-io/reviews?qs=pros-and-cons), [Ziflow/Capterra](https://www.capterra.com/p/178111/Ziflow/reviews/), [Markup/Trustpilot](https://www.trustpilot.com/review/markup.io), [playpause on ReviewStudio](https://playpause.io/blogs/ziflow-vs-reviewstudio)
- **Visual diff exists only as hacks.** psdiff exists so PSDs can use GitHub's image diff; standalone image-diff tools advertise "confirming only the requested areas were touched" for client sign-off. [psdiff](https://github.com/filp/psdiff), [texloom](https://texloom.studio/free-tools/image-diff-compare)

## 4. Video, VFX and post-production

- **Project-file collaboration is broken at the vendor level.** Adobe Team Projects "are literally quietly breaking saving": autosaves stop, Ctrl+S does nothing, "Resolve Conflicts" shows 300+ items; users call it "only usable for small projects." After Effects "doesn't have a way to merge edits made by multiple team members." DaVinci Resolve multi-user needs a PostgreSQL server and the forums are dominated by "Cannot Enable Collaboration." [Adobe Community](https://community.adobe.com/questions-79/team-projects-are-literally-quietly-breaking-saving-1498363), [Adobe Community (AE)](https://community.adobe.com/t5/team-projects-discussions/is-there-a-merge-feature-in-a-team-project-in-after-effects-v-17-02/td-p/11858787), [Blackmagic forum](https://forum.blackmagicdesign.com/viewtopic.php?f=21&t=232087)
- **Proxies and relinking.** Premiere proxies "never remember their file path even after manual relinking"; relinking takes "40+ minutes every time a project opens"; renaming a drive takes all media offline; Productions can't be relocated. Path stability is a first-class need. [Adobe Community (proxies)](https://community.adobe.com/t5/premiere-pro-ideas/better-proxy-relinking/idi-p/13515567), [Adobe Community (relink)](https://community.adobe.com/t5/premiere-pro-discussions/relink-issues/m-p/9404596), [Adobe Community (drive rename)](https://community.adobe.com/t5/premiere-pro-discussions/renamed-hard-drives-media-gone-offline-premiere-2022/td-p/13510229)
- **Frame.io V4** removed comparison mode from the beta, dropped "export timeline markers as comments", reverts markers to old versions, and pushed SMBs toward Enterprise tiers; editors report "having to find alternative software because their entire workflows were messed up." What Frame.io got *right* and people miss: timecode-accurate comments that sync to timeline markers ("the real killer feature"), version stacking with comparison, and no-login review links. [Adobe Community (V4)](https://community.adobe.com/questions-729/frame-io-v4-features-don-t-work-with-legacy-connections-1419243), [Frame.io legacy comparison](https://help.frame.io/en/articles/9084073-frame-io-v4-legacy-feature-comparison), [Frame.io version stacking](https://support.frame.io/en/articles/4431-version-stacking-and-comparison-mode-legacy)
- **Cloud NAS (LucidLink, Suite).** LucidLink: "tendency to disconnect during projects", filespaces crash and pinned footage is lost, service stops when limits are exceeded "without notification", and the 2024 "new LucidLink" is an incompatible product. Suite: "effective rate closer to $75 per terabyte in practice." [AWS Marketplace reviews](https://aws.amazon.com/marketplace/reviews/reviews-list/prodview-fvx4xsqdjwbkg?page=1), [LucidLink FAQ](https://support.lucidlink.com/hc/en-us/articles/31284219950605-FAQ-LucidLink-Classic-and-the-new-LucidLink), [Shade on Suite](https://shade.inc/blog/suite-studios-review-video-production)
- **MAMs and production trackers.** CatDV: "complex and time-consuming" setup, high licensing; EditShare "requires big budgets and dedicated IT support"; Iconik: "adding five contractors for a three-month project means five new seats at full price", slow preview generation; ShotGrid "feels like overkill" for 5–50 person studios and is quote-only; what small studios actually run is "Airtable plus Frame.io." [CatDV/G2](https://www.g2.com/products/catdv/reviews), [Iconik/G2](https://www.g2.com/products/iconik/reviews?qs=pros-and-cons), [animake](https://animake.art/blog/shotgrid-alternatives-small-studios-2026/), [storyflow](https://storyflow.so/blog/autodesk-flow-production-tracking-alternatives-2026)
- **Archive economics.** Restoring 10 TB from Deep Archive costs "roughly a thousand dollars"; cloud bills exceed forecasts by 30–40% due to access and egress charges. [thepostflow](https://thepostflow.com/post-production/archiving-projects-without-losing-your-mind/), [MASV](https://massive.io/file-transfer/cloud-archive-benefits-challenges-and-best-practices)

**Gaps nobody fills** (from the evidence, not from wishful thinking):

- A Git-host-style product (history, reviews, issues, permissions) whose primary object is an image, video or 3D asset with previews and visual diff built in. Diversion has reviews but no DAM; P4 DAM is a paid add-on on a quote-only VCS; Artstash bolts a DAM onto someone else's VCS; Anchorpoint inherits Git's storage model.
- **Anything aimed at agencies, illustrators, motion designers.** Every current vendor's ICP is a game studio. The last attempt at design-team version control was Sketch-only and is now dead.
- Predictable, storage-first pricing with free or unlimited guests (Unity just moved there for games; nobody has for creative teams).
- A cross-platform artist client (everyone is Win/Mac; Blender Studio can't find a maintained multi-OS SVN front end).
- Locks that "just work."
- Layer- or mesh-level diff for PSD, .blend, FBX/USD. Only thumbnails and side-by-side exist anywhere.

## 8. Changes to the plan

Ordered by how much the evidence moves them.

1. **Pull the desktop client forward.** It moves from Phase 4 to Phase 2, in parallel with previews. The research is unambiguous that a DAM which lives outside Photoshop and Premiere gets bypassed, and that the incumbent sync tools (Dropbox, Creative Cloud, Team Projects, LucidLink) are failing on exactly the reliability that matters. Phase 1's web upload flow is for validating the model with a friendly team, not for adoption.

2. **Make locks the headline collaboration feature, not merges.** In the product copy and the UI, "check out" comes before "explore". The evidence says artists and editors understand and want locks, that every implementation they've used is buggy, and that "last save wins" is the loss they fear most. Merges and explorations stay, but they are the second-month feature, as WORKFLOWS.md §11 already implied.

3. **Publish pricing that is storage-based with free guests and included bandwidth.** Proposed principle: a flat per-project or per-org fee that scales with stored GB and includes a generous egress allowance; guests, reviewers and contractors are free and unlimited; no per-feature add-ons; published on the website; changes announced with a year of grandfathering. This is the inverse of every complaint in §1.8 and matches where Unity went in 2026. Add a "Pricing principles" section to VISION.md.

4. **Surface exact-duplicate detection in the UI.** When an upload hashes to an existing blob, say so and show where it already lives. Free, and it answers a named DAM gap. Add to Phase 1.

5. **Resolve the auto-snapshot question toward auto with milestones.** Auto-snapshot on quiet periods, explicit snapshots become milestones shown by default, auto-snapshots squash after 30 days (DESIGN.md §11 already describes the mechanism). The evidence: people already pay for automatic version bumping, and corruption recovery needs the version *before* the last save.

6. **Add "download folder as zip" and release bundles to Phase 1**, not Phase 3. Bulk download friction is a repeated grievance and it is cheap.

7. **State the path-stability guarantee for the desktop client.** The client never renames or relocates files on disk on its own; a project's local folder is a stable root. This is a small design rule with a large payoff for Premiere and Resolve users, and it should be in DESIGN.md §8.

8. **Add an approval record export.** Every release gets a generated PDF: what was approved, by whom, when, with thumbnails, and the review thread. Cheap, and it directly answers the "implied approval" dispute problem. Phase 3.

9. **Never require manual tagging.** Automatic metadata from the preview pipeline, history messages, and issue text carry search; manual tags are optional and never gate upload. Plan OpenSearch for Phase 3 rather than Phase 5, because search that degrades at 100k assets is a named failure mode.

10. **Name the strategic risk.** Add to VISION.md's non-goals/risks: Adobe (or Blackmagic, or Figma) could ship versioning natively for their own files. GitDAM's defence is that no single vendor covers PSD + PRPROJ + BLEND + PDF + exports across an agency's toolchain, that client-facing review and issues are outside those vendors' interest, and that Git-compatible export means adopting GitDAM is never a trap. Keep the product cross-tool on principle; never build a feature that only works for one vendor's format if a format-agnostic version is possible.

11. **Leave room for rights metadata.** `AssetIndex.metadata` is a JSON bag; reserve a `rights` key (licence, expiry, territories, credit) so DAM-style governance can be added without a migration. Not a Phase 1–3 feature.

12. **Cross-platform stays possible.** The Rust core decision in DESIGN.md §8 already keeps a Linux client feasible. Don't spend on it before game/VFX customers ask, but don't design it out.
